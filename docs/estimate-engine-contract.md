# Prosmet Estimate Engine Contract

The Rust `prosmet-estimate-engine` is authoritative for arithmetic used by construction estimates. AI output is input data, not the source of truth for totals.

## Invariants

1. Quantities use milli-units (`1_000 = 1.000` displayed unit).
2. Prices use integer cents.
3. Percentages use basis points (`10_000 = 100%`).
4. Negative quantities, prices, and percentages are rejected.
5. Arithmetic uses integer/fixed-point operations; floating-point is not used for monetary totals.
6. Packaged material quantities are rounded **up** to a whole package.
7. Material waste is applied before package rounding.
8. Overflow is surfaced as a calculation error rather than silently truncated.
9. The UI may display and edit estimate data, but an authoritative recalculation must occur before approval/export.

## Material requirement pipeline

```text
area × consumption
        ↓
net material quantity
        ↓
+ waste
        ↓
required material quantity
        ↓
ceil(required / package size)
        ↓
packages to purchase
```

Reference case:

- area: `180.000 m²`
- consumption: `10.000 kg/m²`
- waste: `10%`
- package: `30.000 kg`
- net: `1,800.000 kg`
- required: `1,980.000 kg`
- purchase quantity: `66 packages`

## Approval boundary

An estimate can be generated by an agent, but it must be recalculated by the deterministic engine before it is treated as an approved financial artifact. Future API implementations should expose the engine result alongside the persisted estimate revision so the calculation is auditable.
