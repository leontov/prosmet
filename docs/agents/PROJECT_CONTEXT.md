# Контекст продукта и критический путь

## Что создаётся

`Просметчик` — chat-first операционная система для строительной организации и самозанятого подрядчика. Пользователь описывает объект обычным сообщением, после чего система формирует технологическую карту, ресурсы, смету, проверку цен и комплект документов. Богатый функционал скрывается за простым интерфейсом в стиле ChatGPT.

Продукт развивается как практический конкурент классу решений 1С и ГРАНД-Смета, но отличается:

- диалоговым входом вместо сложных форм;
- local-first работой;
- региональной памятью цен;
- детерминированным расчётом;
- автоматическим созданием документов;
- встроенной командой ИИ-разработчиков владельца.

## Две главные боли пользователя

### 1. Документация без ручной рутины

Один объект должен связывать:

`исходные данные → технология → ресурсы → цены → смета → версия → КП → договор → счёт → акт → КС-2/КС-3 → архив`.

Суммы и реквизиты не копируются вручную между разными документами. Все документы строятся из утверждённой версии доменной модели.

### 2. Развитие приложения без сторонней IDE

Владелец ставит задачу в чате. A2A-координатор формирует план, делегирует работу специализированным агентам, создаёт проверяемые артефакты, запускает QA и предлагает owner-approved выпуск. Реальные write/git/deploy действия допускаются только через capability gateway, аудит и release gate.

## Основные роли

### Замерщик / мастер на объекте

- преимущественно телефон;
- быстрый ввод текста, файлов и голоса только при настроенном адаптере;
- изменение объёма, единицы и цены;
- offline-first;
- отправка сметы клиенту в несколько касаний.

### Сметчик / руководитель

- преимущественно desktop;
- полный редактор документа;
- источники цен, нормы, коэффициенты и сравнение версий;
- документы и утверждение;
- контроль маржи и исполнения.

### Владелец продукта

- owner-only режим разработчика;
- просмотр плана, diff, тестов, preview и release evidence;
- подтверждение действий с повышенным риском;
- canary, production и rollback.

## Главный пользовательский сценарий

1. Пользователь описывает объект и работы.
2. AI извлекает известные данные и задаёт только блокирующие вопросы.
3. Формируется технологическая карта.
4. Из технологии выводятся работы, материалы, механизмы и логистика.
5. Подбираются цены с provenance и свежестью.
6. Детерминированный движок вычисляет смету.
7. В чат выводится одна компактная карточка с итогом.
8. Карточка открывает адаптивный редактор.
9. Изменения автоматически сохраняются локально и синхронизируются.
10. Пользователь сохраняет версию, утверждает и передаёт клиенту.
11. Из версии формируются документы.

## Текущий критический путь

До добавления новых модулей должен быть безупречно закрыт сценарий:

`сообщение → компактная карточка → редактор → изменение позиции → автосохранение → reload → sync → PDF/XLSX → передача клиенту → desktop/mobile E2E → exact-SHA deploy → HTTPS smoke`.

## Ограничение текущего релиза

Для `PROSMET UX PREMIUM FOUNDATION V1` запрещено расширять продукт новыми крупными модулями. Приоритет:

- HTTPS на `kolibriai.online`;
- отсутствие console errors;
- premium mobile/desktop usability;
- локализация;
- accessibility;
- visual/performance gates;
- зелёный production gate.

## Что не является завершением

- написанный план;
- новый файл в репозитории;
- локально пройденный тест;
- успешный build без deploy;
- скриншот старого релиза;
- PR без merge;
- deploy без exact-SHA проверки;
- ответ агента без наблюдаемого пользовательского результата.
